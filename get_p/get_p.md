如果说 `_get_dxdy` 是 Curve V2 数学引擎中的“前线刺客”，那么 `get_p` 就是运筹帷幄的“总参谋部”。

`get_p` 的全称可以理解为 **Get Price (获取现货价格)**。它的核心任务是计算当前流动性池中，另外两个代币相对于基准代币（Token 0）的**边际现货价格（Marginal Price）**。这是 Curve V2 内部预言机（EMA Oracle）和动态费用调整机制运转的最重要基石。

上一篇我们讲到，`_get_dxdy` 需要利用三个神奇的多项式参数 `a, b, c` 来完成隐函数求导的最后一步拼图。
而 `get_p` 的核心使命，就是**把复杂的 AMM 恒等式，硬生生地拆解并组装成这三个纯多项式 `a, b, c**`。

为了讲透它的数学逻辑，我们来看看它是如何把数学公式展开，并映射成 EVM 极致优化代码的。

---

### 第一步：前因 —— 为什么要拆解成多项式？

Curve V2 的基础恒等式非常复杂。正如我们在 `_get_dxdy` 分析中所指出的，为了利用隐函数求导得出价格（即 $\frac{\partial F}{\partial x_1} / \frac{\partial F}{\partial x_0}$），数学家提取了一个用于计算偏导数的宏观结构：

我们需要构造一个关于聚集度 $K$（其中 $K = 27 \frac{x_0 x_1 x_2}{D^3}$）的核心多项式 $a$：

$$a = (K - \gamma - 1)^3 + A\gamma^2(K + \gamma + 1)$$

但是，在智能合约里，直接去算 $K$，然后再算它的三次方，意味着要进行大量的浮点和小数运算，不仅消耗极大 Gas，还极容易发生精度丢失甚至溢出。

**Curve 的绝妙操作是：在草稿纸上把 $a$ 彻底展开，合并同类项，把所有的除法和分数都提前用常数消化掉！**

我们将 $a$ 按照 $K$ 的幂次方（$K^3, K^2, K^1, K^0$）在数学上展开：

$$a = \mathbf{K^3} - \mathbf{3(\gamma + 1)K^2} + \mathbf{[3(\gamma + 1)^2 + A\gamma^2]K} + \mathbf{[A\gamma^2(\gamma + 1) - (\gamma + 1)^3]}$$

现在，见证奇迹的时刻到了。请看代码中的 `s1, s2, s3, s4`，它们正是这四个项在代码中的完美化身！

### 第二步：解构代码中的“魔法数字” (`s4, s3, s2, s1`)

在代码中，并没有直接计算 $K$。因为 $K = 27 \cdot \frac{x_1 x_2 x_3}{D^3}$，所以 $\frac{x_1 x_2 x_3}{D^3} = \frac{K}{27}$。
为了消除除以 27 带来的浮点数，工程师在代码里硬编码了 $27$ 的各级幂次方：**$27^1 = 27$，$27^2 = 729$，$27^3 = 19683$**。

我们倒序来看 `s4` 到 `s1`：

**1. `s4` —— 对应 $K^3$ 项**
代码实现：`s4: int256 = 10**18*19683*x1/D*x1/D*x1/D*x2/D*x2/D*x2/D*x3/D*x3/D*x3/D`

忽略精度缩放，它的代数本质是：$19683 \cdot (\frac{x_1 x_2 x_3}{D^3})^3$。
因为 $\frac{x_1 x_2 x_3}{D^3} = \frac{K}{27}$，代入进去：
$s_4 = 19683 \cdot (\frac{K}{27})^3 = 27^3 \cdot \frac{K^3}{27^3} = \mathbf{K^3}$。
完美对应展开式的第一项！

**2. `s3` —— 对应 $3(\gamma + 1)K^2$ 项**
代码实现：`s3: int256 = 2187*(10**18 + gamma)*x1/D*x1/D*x2/D*x2/D*x3/D*x3/D`

其中 2187 是怎么来的？$2187 = 3 \times 729 = 3 \times 27^2$。
代数本质：$3 \cdot 27^2 \cdot (\gamma + 1) \cdot (\frac{x_1 x_2 x_3}{D^3})^2$
代入 $\frac{K}{27}$：
$s_3 = 3 \cdot 27^2 \cdot (\gamma + 1) \cdot \frac{K^2}{27^2} = \mathbf{3(\gamma + 1)K^2}$。
完美对应展开式的第二项！(代码后面在组合时写的是 `- s3`，正好把负号补上)。

**3. `s2` —— 对应 $[3(\gamma + 1)^2 + A\gamma^2]K$ 项**
代码实现：`s2: int256 = 81*(10**18 + gamma*(2*10**18 + gamma + 10**18*9*A/27/10000*gamma/10**18)/10**18)*x1/D*x2/D*x3/D`

这里的 81 是 $3 \times 27$。括号里看似混乱，但如果把它化简：
$1 + \gamma(2 + \gamma + \frac{A}{3}\gamma) = 1 + 2\gamma + \gamma^2 + \frac{A\gamma^2}{3} = (\gamma+1)^2 + \frac{A\gamma^2}{3}$。
把它与外面的 3 相乘：$3(\gamma+1)^2 + A\gamma^2$。
再结合外面的 27 和代币乘积：
$s_2 = 27 \cdot [3(\gamma+1)^2 + A\gamma^2] \cdot (\frac{K}{27}) = \mathbf{[3(\gamma + 1)^2 + A\gamma^2]K}$。
再次完美对应！

**4. `s1` —— 对应常数项 $A\gamma^2(\gamma + 1) - (\gamma + 1)^3$**
代码实现：`s1: int256 = (10**18 + gamma)*(-10**18 + gamma*(-2*10**18 + (-10**18 + 10**18*A/10000)*gamma/10**18)/10**18)/10**18`

这一项不包含代币余额，纯粹是参数计算。化简这段代码代数：
$(1+\gamma) \cdot [-1 + \gamma(-2 - \gamma + A\gamma)]$
$= (1+\gamma) \cdot [-1 - 2\gamma - \gamma^2 + A\gamma^2]$
$= (1+\gamma) \cdot [-(1+\gamma)^2 + A\gamma^2]$
$= \mathbf{A\gamma^2(\gamma + 1) - (\gamma + 1)^3}$。
丝毫不差！

**最后，将这四个碎片拼起来：**
`a: int256 = s1 + s2 + s4 - s3`

至此，最核心的参数 `a` 构建完成。

### 第三步：辅助项 `b` 和 `c` 的构建

除了主项 `a`，求导公式还剥离出了两个线性修正项 `b` 和 `c`。它们的数学定义是：

$$b = \frac{A \gamma^2 K}{D}, \quad c = \frac{A \gamma^2 (\gamma + 1)}{D}$$

我们看看代码是怎么实现的：
**关于 `b**`：
`b: int256 = 10**18*729*A*x1/D*x2/D*x3/D*gamma**2/D/27/10000`

化简后：$b = \frac{729 \cdot A \cdot (x_1 x_2 x_3) \cdot \gamma^2}{27 \cdot D^3 \cdot D} = \frac{27 \cdot A \cdot \gamma^2 \cdot (\frac{x_1 x_2 x_3}{D^3})}{D}$。
代入 $K$ 之后就是 $\mathbf{\frac{A \gamma^2 K}{D}}$。

**关于 `c**`：
`c: int256 = 27*A*gamma**2\*(10**18 + gamma)/D/27/10000`

化简后正好就是 $\mathbf{\frac{A \gamma^2 (\gamma + 1)}{D}}$。

这两项的作用是根据当前池子的总深度 $D$ 来约束导数变化的剧烈程度。

### 第四步：后果 —— 移花接木，调用 `_get_dxdy`

经过了前面堪称艺术的参数提取和多项式组装，`get_p` 已经准备好了 `a, b, c` 这三个最终武器。
接下来它要做的是返回两个价格：代币 1 相对 代币 0 的价格，以及 代币 2 相对 代币 0 的价格。

在 `get_p` 中，局部变量的映射是这样的（注意 Vyper 是 0 索引，代码中的 `x1` 实际是 Token 0）：
`x1` = 池子代币 0
`x2` = 池子代币 1
`x3` = 池子代币 2

为了计算 Token 1 相对 Token 0 的价格（即 $\frac{F_0}{F_1}$），`get_p` 发起了一次精妙的“参数换位”调用：

```vyper
return [
    self._get_dxdy(x2, x1, x3, a, b, c),
    self._get_dxdy(x3, x1, x2, a, b, c),
]

```

我们在上一篇讲到过，`_get_dxdy` 内部计算的逻辑固定是：$\frac{-(传入代币1的偏导数)}{(传入代币0的偏导数)}$。

- 当它调用 `_get_dxdy(x2, x1, x3, a, b, c)` 时，它故意把代表 Token 1 的 `x2` 放在了第一个参数位，把代表 Token 0 的 `x1` 放在了第二个参数位。

- 这样一来，底层 `_get_dxdy` 算出的就恰好是 $\frac{F_{x1}}{F_{x2}}$，也就是 $\frac{F_0}{F_1}$。这正是 **Token 1 以 Token 0 计价的精确现货价格**！
- 同理，第二个调用 `_get_dxdy(x3, x1, x2, ...)` 算出的就是 **Token 2 相对 Token 0 的现货价格**。

### 总结

`get_p` 展现了极高的“EVM 算术优化美学”：

为了求一个包含各种分数、立方的导数，Curve 的数学家**拒绝在链上做除法**。他们预先在草稿纸上完成了庞大复杂的泰勒展开式合并，然后把常数（如 19683, 2187, 81）硬编码到合约里，通过提取共同的多项式因子 `a, b, c`，在 EVM 里仅仅使用最便宜的乘法和加法，就拼凑出了一个宏大的隐函数导数结构。最后只需一次除法，就输出了精准的无损价格。
